# VARUNA — engineering handoff

_Last verified: 2026-08-29. Branch `ayush-integration`._

## 1. What VARUNA does

VARUNA turns a **real Sentinel‑1 SAR observation** of the sea surface into a ranked list of
**candidate vessels** that may be associated with a detected oil slick, with every number
traceable to its source and every missing input surfaced as a stated limitation rather than
hidden.

Pipeline:

```
Sentinel-1C RTC scene (Microsoft Planetary Computer)
  → windowed COG read → MinIO object storage → TiTiler XYZ tiles
  → classical dark-spot detection (13 detections)
  → backward-drift origin estimate  (DEGRADED / FOOTPRINT_PROXIMITY without ocean forcing)
  → AIS correlation over the origin envelope   (synthetic demo AIS today)
  → evidence-weighted candidate ranking  (capped at MODERATE while origin is degraded)
  → investigation dossier (all mandatory sections, exportable)
```

`services/ml` (separate Python project).

## 4. Demo flow (2 ways)

**One command** (stack must be up):

```bash
docker compose up -d
pnpm demo
```

Prints a workspace URL, a dossier URL and demo login credentials. See
[DEMO-SCRIPT.md](DEMO-SCRIPT.md) for the click-through narration.

**Manual, through the UI:** register → New investigation (AOI `144.55,13.30,144.95,13.60`,
window `2025-09-20 … 2025-09-23`) → paste product id
`S1C_IW_GRDH_1SDV_20250921T200737_20250921T200800_004227_008638_rtc` → Ingest and detect →
Origin → Run back-tracking → Rank candidate vessels → Dossier.

Reset between runs: `pnpm demo:reset` (clears analysis collections + `scenes/` in MinIO;
keeps users, volumes, containers).

## 5. REAL vs SYNTHETIC vs DEGRADED

| Element | Status | Notes |
|---|---|---|
| Sentinel‑1C RTC scene, COGs, tiles | **REAL** | Microsoft Planetary Computer, Copernicus Sentinel data |
| Detections | **DERIVED** | classical dark-spot detector over the real scene |
| AIS slice | **SYNTHETIC** | `data/demo/ais/guam-2025-09-21.demo.csv`, generated by `scripts/data/make-demo-ais.mjs`, imported with `--demo` so provenance says "VARUNA synthetic demo AIS" |
| Candidate ranking | **INFERRED** | live evidence-weighted score; capped at MODERATE |
| Origin estimate | **DEGRADED** | `FOOTPRINT_PROXIMITY` — no keyless ocean/wind forcing for the date |

## 6. Current limitations

1. **Ocean-current / wind forcing** — origin analysis is always `DEGRADED` locally because
   HYCOM's keyless archive ends 2024‑09‑05 and the 2025 scene falls in the gap. Real
   back-tracking needs CMEMS + CDS credentials (see [DATA-AND-CREDENTIALS.md](DATA-AND-CREDENTIALS.md)).
2. **Real AIS** — only the labelled synthetic slice is wired. The import path, provenance
   labelling and `--demo` flag are in place; a real provider needs a credential + a small
   adapter.
3. **Live socket refresh** — a couple of side panels (Origin, Candidates) need a manual
   refresh to pick up a just-finished job; data itself is always correct.
4. **UI polish** — the workspace, dossier and theme system are solid; the dashboard / vessel
   explorer / settings pages described in the sprint brief are **not yet built** (see §7).
